Ainekio's onboard microcontroller (`ESP32-P4` on V2, `ESP32-S3` on V1; [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot)) and **[Ainekio OS](/posts/ainekio-os/)** communicate across a strict wire and safety boundary called **`protocol-v1`**. Language models never write raw PWM duty cycles to servo pins; cognition proposes high-level postures, bounded velocity twists, or structured target programs, and onboard C firmware enforces calibration, linkage geometry, slew limits, shaft arrival, and emergency stop rules.

## Binary and JSON framing over `protocol-v1`

An authenticated WebSocket session carries both structured control envelopes and low-overhead media streams without blocking motor execution:

- **JSON control & telemetry envelopes**: Carry capability handshakes (`hello`), sequence-numbered movement commands, parameter updates, lifecycle receipts, `208 Hz` `LSM6DS3` attitude summaries, 12-channel servo tracking health, and thresholded body-contact events.
- **Binary media frames**: Stream correlated `OV5647` JPEG camera stills/previews and bidirectional `16 kHz` 16-bit mono PCM audio bursts (`640 bytes` per `20 ms` frame) with explicit burst headers and utterance/sequence IDs so media traffic never starves control-loop parsing.

### Command categories across V1 and V2

| Command Category | Purpose & Firmware Validation Boundary |
| --- | --- |
| **Named postures & gaits** | Prepared postures (`Stand`, `Sit`, `Rest`, `Lay Down`, `Play Dead`, `Upright`), continuous analytical gaits (`Walk`, `Run`, `Crawl`, `Crab`), and 23 finite gestures (`Wave`, `Bow`, `Stretch`, `Worm`, `Shrug`) |
| **On-chip neural twist (`50 Hz`)** | Bounded velocity twists (`-0.22..+0.20 m/s` fore/aft, `±0.08 m/s` strafe, `±1.0 rad/s` yaw) executed directly on Core 1 by the L2-cached `107.8 KB` `int8` MicroDuck actor |
| **In-stride gait updates** | Adjusts `Speed`, `Stride %`, `Motion rate`, or steering heading on an active V2 walk while preserving the gait phase and active command lease |
| **Freestyle target programs** | Finite sequences of 12-DOF joint, foot, or body targets with explicit speeds, holds, and **59** LCD expressions from the **349-motion** library (**489-row** training set: **73** library motions + **416** `Stand` fault-recovery trajectories) |
| **Host neural policy frames (`50 Hz`)** | Streamed 12-joint target offsets from host RL policies, clamped by firmware calibration and Cartesian workspace projection |
| **Emergency `stop`** | High-priority direct path that preempts queued work, halts active motion immediately, and parks or detaches the actuators |

## Closed-loop hardware safety on V2

On the twelve-servo `ESP32-P4` body, safety checks operate continuously from boot through dynamic walking:

1. **Disarmed boot & startup slew limiting**: On power-up, the `PCA9685` output-enable line stays disarmed until joint calibration and initial `CD74HC4067` potentiometer readings are acquired. Rather than snapping all twelve servos violently to a neutral angle at full stall current, startup ramps smoothly from the measured resting shaft angles into a staged boot posture under bounded angular slew rates, while `PCA9685` PWM channels use staggered phase offsets across the `50 Hz` frame to prevent `5 V` rail brownouts.
2. **8-pass Gauss-Newton Cartesian workspace projection**: Because each V2 leg uses a coupled `35/20/28/38/55 mm` four-bar linkage, arbitrary `(x, y, z)` foot requests or neural offsets (`[45, 28, 30] mm` action scale) can fall outside the closed-chain kinematic envelope. Firmware projects out-of-bounds Cartesian targets onto the nearest reachable boundary via analytical four-bar IK, 8-pass Gauss-Newton Jacobian refinement, and 13 dyadic step fractions before driving the servos—preventing linkage lockup against hard stops.
3. **4th-wire shaft-arrival & stall protection (`CD74HC4067`)**: Every servo's internal potentiometer wiper routes through multiplexer channels **`C4–C15`** (selected via `S0–S3` on `GPIO28–31`) into `ESP32-P4` **`GPIO49` (`ADC2_CH0`)** with One-Euro velocity filtering. In `Stand` (which settles within **`2 mm`**) and Freestyle programs, steps advance on measured shaft arrival rather than blind timers. Comparing commanded motion against measured wiper velocity and `208 Hz` `LSM6DS3` attitude catches limb stalls, rug snags, tips, and shakes in real time.

## Command lifecycle states, leases, and watchdogs

Writing bytes to a socket only proves the network accepted the packet. `protocol-v1` tracks every command across explicit lifecycle states keyed by `command_id`, connection epoch, and sequence number:

| Receipt State | Meaning |
| --- | --- |
| `ack` | The microcontroller validated capabilities, workspace bounds, and readiness, and accepted the command |
| `done` | Physical motion or audio playback completed on the body (including verified shaft arrival where enabled) |
| `cancelled` | Accepted work was preempted by `stop`, a newer command, or session teardown before finishing |
| `nak` | Rejected as out of range, malformed, or unsupported by current hardware readiness |
| `outcome_unknown` | Recorded by the gateway adapter if Wi-Fi drops after dispatch before a terminal body receipt can be verified |

### Leases, heartbeats, and non-repeating reconnect recovery

- **Command leases & liveness watchdogs**: Continuous walking and neural velocity twists run under bounded command leases backed by bidirectional application heartbeats. If control packets stall mid-walk, the onboard watchdog halts locomotion smoothly while keeping an otherwise healthy idle session alive; on full Wi-Fi loss, the robot enters local failsafe behavior and relaxes into inactivity `Rest` after extended quiet.
- **Capability advertising**: The controller dynamically advertises `camera_ready`, wake-engine readiness (`WakeNet9s`), and 12-DOF V2 vs. 8-DOF V1 motion capabilities so the gateway never exposes unavailable actions to Ainekio OS.
- **Idempotent SQLite recovery**: Because every action's ID, payload hash, epoch, and sequence number are persisted before dispatch, reconnecting after a network drop reconciles the existing sequence or settles it as `outcome_unknown`—never blindly re-sending a physical movement command twice.
