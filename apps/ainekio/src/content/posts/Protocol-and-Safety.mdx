Ainekio's onboard controller (`ESP32-P4` on V2, `ESP32-S3` on V1) and **[Ainekio OS](/posts/ainekio-os/)** (formerly MetaHuman OS) communicate through a strict boundary called **`protocol-v1`**. Language models never write raw PWM duty cycles directly to servo pins; instead, cognition selects high-level semantic intents, locomotion goals, or structured target programs, and the onboard firmware enforces calibration, workspace geometry, shaft arrival, and emergency stop rules.

## Command categories across V1 and V2

| Command Type | Purpose & Validation Boundary |
| --- | --- |
| **Named commands (`robotCommand`)** | Prepared postures (`Stand`, `Sit`, `Rest`, `Lay Down`, `Play Dead`, `Upright`), continuous gaits (`Walk`, `Run`, `Crawl`, `Crab`), and 23 expressive gestures (`Wave`, `Bow`, `Stretch`, `Worm`, `Shrug`, etc.) |
| **On-chip neural twist (`native`, `50 Hz`)** | Commands velocity twists (`-0.22..+0.20 m/s` fwd/rev, `±0.08 m/s` strafe, `±1.0 rad/s` yaw) executed directly on Core 1 by the L2-cached `107.8 KB` `int8` MicroDuck policy (`0.8.159-p4-microduck-v17`) |
| **Continuous gait updates** | Adjusts `Speed`, `Stride %`, `Motion rate`, or steering heading on an active V2 walk while preserving the gait phase and command lease |
| **Freestyle target programs** | Finite sequences of 12-DOF joint, foot, or body targets with requested speeds, holds, and LCD faces from the 349-example SQLite library (`489`-row training set with native-`stand` recovery) |
| **Host neural policy frames (`neural`, `50 Hz`)** | Streamed 12-joint target offsets from host RL policies (`pupper_mjx_actor.py`), bounded by firmware calibration and workspace projection |
| **Emergency `stop`** | High-priority direct path that preempts queued work, halts active motion immediately, and parks or releases the actuators |

## Closed-loop safety and workspace enforcement on V2

On the twelve-servo `ESP32-P4` body, command validation extends beyond static angle clamping to real-time geometric and physical verification:

1. **8-pass Gauss-Newton Cartesian workspace boundary projection (`0.8.150+`)**: Because each leg uses a coupled `35/20/28/38/55 mm` linkage, arbitrary `(x, y, z)` foot requests or neural offsets (`[45, 28, 30] mm` action scale) could fall outside the closed-chain kinematic envelope. Firmware projects out-of-bounds Cartesian targets onto the nearest reachable boundary via analytical 4-bar IK, 8-pass Gauss-Newton Jacobian refinement, and 13 dyadic step fractions before driving the servos, preventing linkage lockups and hard mechanical stops.
2. **4th-wire shaft-arrival verification (`CD74HC4067`)**: Every servo's internal potentiometer wiper is sampled through the 16-channel analog multiplexer and smoothed by a One-Euro velocity filter. In `Stand` (which settles within **`2 mm`**) and Freestyle target programs, the controller checks measured shaft arrival against the commanded angle rather than assuming completion from elapsed time alone.
3. **Physical jam, stall, and tip detection**: By comparing commanded trajectories against measured `CD74HC4067` potentiometer movement and `208 Hz` `LSM6DS3` `FusionAhrs` attitude, the firmware detects limb jams/stalls, tips, and shakes, emitting immediate body events so `fast-body-event-mode.json` (6-turn varied reactions) or Freestyle native-`stand` recovery can respond safely.
4. **Staggered `PCA9685` pulse phases**: To minimize instantaneous current spikes on the `Mini560` `5 V / 5 A` rail, the twelve servo PWM channels use staggered phase offsets across the `50 Hz` frame.

## Command lifecycle states

Sending bytes over a WebSocket only proves that the network socket accepted the frame. `protocol-v1` tracks every command through explicit lifecycle states correlated by `command_id`, connection epoch, and sequence number:

| State | Meaning |
| --- | --- |
| `ack` | The robot controller validated and accepted the command for execution |
| `done` | The physical motion or media action finished on the body (including verified shaft arrival where enabled) |
| `cancelled` | Accepted work was preempted by `stop`, a newer command, or session termination before completion |
| `nak` | The request was rejected as invalid, out of range, or unsupported by the current readiness state |
| `outcome_unknown` | Adapter-level receipt state recorded when a connection drops after dispatch before a terminal body result can be verified |

In Ainekio OS, `done` settles the **command** receipt, while **Goal Review** checks whether the broader **objective** is satisfied—for example, inspecting a correlated post-motion camera frame or depth odometry reading before marking a visual approach complete.

## Capability and readiness advertising

The robot dynamically reports both its hardware **capabilities** and live **readiness** to the Host Gateway:

- Camera snapshots and visual tracking require `camera_ready = true` (`OV5647` on V2, `OV3660` on V1).
- Wake-gated voice capture requires an initialized wake engine (`WakeNet9s` on V2).
- 12-DOF Freestyle, leveling, and on-chip / host neural gait controls are advertised only by V2 `ESP32-P4` sessions.

The gateway and adapter filter the schema presented to Ainekio OS so the language model is only offered actions the currently connected robot can actually perform, and operators can pause Ainekio OS control at any moment from the Cockpit HUD / Body Control top bar.

## Disconnect failsafes and non-repeating recovery

- **Control liveness & failsafe**: Periodic application heartbeats verify control-path liveness. If control traffic stalls during active locomotion, the firmware halts movement without dropping an otherwise healthy idle session. On full WebSocket or Wi-Fi loss, the body enters local failsafe behavior and optionally relaxes into inactivity `Rest`.
- **Idempotent SQLite action receipts**: The adapter records each action's ID, payload hash, gateway instance, connection epoch, and robot sequence in SQLite before dispatch. If a connection interruption occurs after a movement has started, recovery tracks the existing sequence or settles it as `outcome_unknown`—never blindly re-sending a physical movement command twice.
