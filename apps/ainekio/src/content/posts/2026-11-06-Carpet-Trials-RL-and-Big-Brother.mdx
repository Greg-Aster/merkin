Between November 2 and November 6, work progressed from physical carpet refinement and
ESP32-P4 camera/IMU odometry upgrades to training a **200-million-step neural gait
policy in JAX 0.7.1 / Brax / MuJoCo MJX**—resolving both early miniature-hopping and
reverse rear-dragging ("scootybooty") failure modes—and deploying that policy onto the
**650 g physical V2 quadruped** for its first real-life neural network walk. In
parallel, MetaHuman OS unified its local `llama-cpp.service` runtime, Big Brother
(`gpt-6-sol` / Codex) delegation, and HTTP API router.

## First real-life neural network walk on the physical 650 g V2 robot

After exporting the full 376-mesh Blender V2 CAD assembly into MuJoCo MJCF and resolving
the simulation stride and posture issues described below, we deployed the trained neural
policy onto the physical 12-servo Ainekio V2 quadruped on carpet. The robot now walks
forward and reverses cleanly under closed-loop neural control without dragging its rear
assembly:

## Quadruped RL in MuJoCo/MJX: from tiny hops and "scootybooty" to a centered 200M-step stride

To move beyond open-loop keyframe tables and pure imitation learning, we integrated
**Walk in the Park (DroQ)**, **Microduck RL**, a verified **Stock Pupper V3 MuJoCo
baseline** (`+1.68 m` forward walk; [watch in the Gallery](/gallery/#pupper-v3-mujoco-baseline)),
and a **full-CAD Ainekio V2 MJCF model** (`0.650 kg`, 12 servo actuators, 8 passive
hinges, and 4 planar four-bar loop-closure equality constraints) wired into
`jax_hardware.py` for GPU training in **JAX 0.7.1 / Brax / MJX**.

Getting the closed-chain four-bar model to walk naturally in both forward and reverse
required diagnosing and fixing two classic reinforcement-learning failure modes across
successive training runs:

### 1. Failure mode #1: Rapid tiny hops (`35M`-step narrow-scale rollout)

In our initial 35-million-step full-CAD run (`ainekio_full_cad_35M_policy.mp4`),
conservative action scaling constrained joint excursions so tightly that the policy
discovered it could track forward velocity by vibrating its feet in rapid miniature hops
(`20–27 mm` fore-aft foot swing) rather than sweeping through a real stride:

### 2. Failure mode #2: Asymmetric split stance & "scootybooty" reverse dragging (`200M`-step Run #4)

Widening the action scale eliminated the tiny hops, but in the next 200-million-step
run (`Run #4`, `ainekio_wide_stride_200M_policy.mp4`), the policy parked its rear legs
in an asymmetric split stance (`RL` parked forward at `-54.3 .. -30.7 mm`, `RR` parked
back at `-92.3 .. -72.0 mm`). Worse, when commanded to walk backward (`-0.10 m/s`), the
robot lowered its rear torso to **`0.044 m`** and dragged/scooted its back end along
the floor—nicknamed **"scootybooty"**—instead of lifting its rear feet cleanly:

### 3. Resolved 200M-step centered-stride & upright reverse policy (`Run #5`)

By penalizing off-center foot parking and shaping foot air-time and orientation
tracking across a fresh 200-million-step MJX run (`Run #5`,
`policy_2026-11-05_20-13-42.json`), both failure modes were eliminated:

- **`eval/episode_feet_air_time`** jumped **`3.5×`** (from `157.29` in Run #4 to **`557.11`** in Run #5).
- **`eval/episode_reward`** reached **`28.97 ± 13.18`**, with **`0.0` body collisions** and **`0.0` knee collisions**.
- **Fore-aft foot stride (`X_body`)** widened **`2.2×–2.8×`** to **`56.6–63.7 mm`** across all four legs, centered cleanly around each leg's home stance (`-59.2 mm` rear, `+74.2 mm` front).
- **Upright reverse walking:** During `-0.10 m/s` reverse commands, final torso height improved from `0.044 m` to **`0.072 m`** (`rear_z_min = 0.060 m`) with zero rear dragging.

## Physical carpet trials (`20261102-forward-refinement`) and onboard OV5647 video

Prior to deploying the 200M-step MJX policy, our November 2 physical carpet refinement
trials (`20261102-forward-refinement`) logged **601 physical state transitions** under
load while capturing live video from the onboard OV5647 camera:

- **Watch the onboard camera footage:** [Physical Carpet Trial (`20261102-forward-refinement`) in the Gallery](/gallery/#carpet-trial-20261102)

Running gait learning over real carpet highlighted how motion blur, rolling frame
timestamps, and foot-boundary projection affect visual odometry and safety bounds,
driving four targeted ESP32-P4 firmware upgrades:

| Firmware revision | Physical sensing & audio improvement |
| --- | --- |
| **`0.8.138`** | Configurable **15-second** Espressif **WakeNet9s / VAD** voice recording window after wake-word detection |
| **`0.8.139-p4-motion-exposure`** | Enforces a **10,000 µs (10 ms)** camera exposure ceiling during movement to prevent motion blur from corrupting visual landmark tracking |
| **Frame completion + IMU SLERP** | Tags every captured frame with its exact end-of-exposure timestamp and interpolates IMU quaternions for **OpenGV 2-point RANSAC** depth odometry |
| **`0.8.150-p4-foot-projection`** | Calibrated Cartesian foot-boundary projection so workspace limits match physical linkage reach under load |

## Freestyle Big Brother SSH inference (`gpt-6-sol` / Codex fast mode)

Alongside local Qwen LoRA serving via `llama-cpp.service`, the Freestyle motion
generator now supports a remote **Big Brother** inference provider via
`--big-brother-ssh`, routing complex or novel motion synthesis requests to
**`gpt-6-sol` / Codex fast mode** over SSH while keeping local `llama.cpp` ready for
low-latency offline operation.

## MetaHuman OS runtime and Big Brother consolidations

On the cognitive host, we completed a sweeping architectural consolidation across
terminal interfaces, Big Brother delegation, environment bridging, and the HTTP API
router:

| Subsystem | Consolidation milestone |
| --- | --- |
| **Unified terminal subsystem** | Consolidated terminal and chat interactions into a single **`TerminalChat.svelte`** component |
| **Async computer task delegation** | Standardized asynchronous coding and system task delegation through **`big-brother-tool-mode.json`** |
| **Automated code review agent** | Added a dedicated **`system-code-review`** agent for automated repository and architecture checks |
| **Single Environment Bridge** | Unified robot communication under a single **`environment-bridge`** runtime owner and **`environment-mode.json`** workflow |
| **Core API router (`[...path].ts`)** | Replaced **257 individual wrapper route files** with a single canonical catch-all **`[...path].ts`** Core API router |
