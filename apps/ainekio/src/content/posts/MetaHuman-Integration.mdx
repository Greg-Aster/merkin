While **[Ainekio OS](/posts/ainekio-os/)** ([`Greg-Aster/ainekio-os`](https://github.com/Greg-Aster/ainekio-os), formerly MetaHuman OS) owns identity, episodic memory, cognitive graphs, and model routing, and [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot) owns the physical quadruped firmware and host gateway, the **Embodied Bridge** is the narrow, event-driven connection between those two worlds.

Instead of letting a language model poll hardware sensors or stream raw servo angles over Wi-Fi, the bridge translates physical robot state into structured multimodal observations flowing upward, and translates high-level cognitive decisions into checked motion, facial, and speech intents flowing downward.

## Connection topology and robot following

The bridge connects Ainekio OS to the robot's **Host Gateway** ([gateway guide](/posts/gateway-and-simulator/)) across whichever link is active—local workstation loopback, home Wi-Fi LAN, an edge `Radxa Dragon Q6A` board, an SSH tunnel, or an optional remote tunnel.

- **Single authoritative stream**: Multi-host connection following keeps one active observation and action session pinned to the physical robot (supporting both the 12-servo `ESP32-P4` V2 body and the earlier 8-servo `ESP32-S3` V1 frame) so switching between bench and living-room hosts never spawns duplicate command streams.
- **Instant operator override**: A top-bar switch in the Body Control workbench and Cockpit HUD pauses or resumes Ainekio OS control immediately without dropping telemetry or manual teleoperation.

## Upward flow: how sensory data and telemetry enter Ainekio OS

Not every hardware reading should trigger a language-model call. The bridge separates high-rate background telemetry from discrete events that warrant cognitive attention:

| Upward Signal | Source on V2 Body & Gateway | How Ainekio OS Consumes It |
| --- | --- | --- |
| **Live Robot Status** | `208 Hz` `LSM6DS3` attitude, battery voltage, active posture, and 12-channel `CD74HC4067` (`C4–C15` → `GPIO49`) servo tracking health | Updates live context quietly in the background without firing redundant conversational turns |
| **Voice Transcripts** | `WakeNet9s` wake-gated `16 kHz` audio from the `ES8311` codec, segmented by 5-mode VAD and transcribed by Whisper ([voice guide](/posts/voice-loop/)) | Enters the embodied workflow as an attributed spoken turn, optionally paired with a camera still taken at utterance end |
| **Correlated Camera Snapshots** | Chin-mounted `OV5647` MIPI-CSI stills (explicit captures, post-motion verification frames, or tracked object crops; [vision guide](/posts/vision-loop/)) | Tagged with the exact `action_id`, `command_sequence_id`, or `utterance_id` so vision grounding knows *when* and *why* the frame was captured |
| **Spatial & Obstacle Metrics** | Cockpit HUD optical-flow + monocular depth obstacle range, YOLOE target boxes, and OpenGV / MoGe depth odometry | Supplies measured forward progress, heading change, and approach clearance during locomotion goals |
| **Body-Contact Events** | Thresholded `tipped`, `shaken`, `stalled` / `jammed`, and `boot` events from the IMU and 4th-wire servo wipers | Routes sudden jostles to the fast body-reflex workflow, and routes `boot` / wake transitions to full contextual orientation |

## Downward flow: how cognitive intents become robot actions

When an observation enters Ainekio OS's embodied workflow, four distinct cognitive roles split the work so outward speech stays natural and physical actions stay bounded:

1. **Intent Orchestration**: Classifies whether incoming input is a new request, a mid-walk adjustment, a cancellation, or pure conversation, and decides whether a spoken reply is appropriate.
2. **Task Selection**: Picks concrete, schema-validated robot intents—named postures or gaits (`Stand`, `Walk`, `Run`, `Crawl`, `Crab`, or 23 gestures), measured locomotion goals (distance, turn angle, visual approach/follow using on-chip `50 Hz` MicroDuck or analytical gaits), **Freestyle** 12-DOF target programs (backed by the **349-motion** library and **489-row** training set of **73** library motions + **416** `Stand` fault-recovery trajectories), explicit camera snapshots, or background coding delegations—without injecting robotic step-by-step narration between movements.
3. **Goal Review**: Inspects the returned hardware action receipt, shaft-arrival telemetry, and post-motion camera frame before marking a multi-step physical objective complete or selecting a follow-up step.
4. **Outward Expression (Standing Persona, Face & Voice)**: Synthesizes the single conversational reply in Ainekio's voice, pairs it with one of the **59 animated expressions** on the `1.9"` `ST7789` LCD, and streams paced Kokoro or Piper audio to the `NS4150B` speaker while holding an explicit self-speech suppression window so the microphone ignores playback.

## Fast body-contact reflexes vs. durable multi-step tasks

Physical contact and multi-step errands operate on very different timescales, so the bridge gives each its own execution path:

- **Sub-second jostle & stall reflexes**: When the `ESP32-P4` reports that Ainekio was tipped, shaken, or stalled against a rug seam, the event routes to a lightweight single-call reflex workflow rather than full task planning. To keep reactions fresh when someone picks the robot up repeatedly, the reflex prompt includes the **last 6 body-event remarks** with diversity penalties, emitting a matching LCD reaction face and a dry, non-repetitive comment without derailing an in-progress goal.
- **Crash-safe receipts across Wi-Fi drops**: Multi-step tasks (such as standing up, walking across a room, snapping a verification photo, and reporting back) suspend cleanly in SQLite while the body moves. Before dispatching any command over `protocol-v1` ([protocol guide](/posts/protocol-and-safety/)), the gateway adapter records its action ID, payload hash, connection epoch, and sequence number. Every command settles to an explicit terminal state (`done`, `cancelled`, `nak`, or `outcome_unknown` if Wi-Fi drops mid-move), ensuring that reconnect recovery **never blindly replays a physical movement twice**.
