[MetaHuman OS](https://github.com/Greg-Aster/metahuman-os) is the cognitive runtime behind Ainekio's conversation, memory, identity, perception, and autonomous planning. While the onboard `ESP32-P4` controller owns real-time servo loops and hardware safety limits, MetaHuman OS turns multimodal observations and user requests into durable, multi-step executions and spoken companion responses.

For a high-level view of how personality, sleep maintenance, and memory work together, see [Ainekio as a Companion](/posts/ainekio-companion/).

## Unified inference architecture (`llama-cpp.service`)

All local language, vision, specialist, motion, and embedding inference runs through a **single consolidated `llama-cpp.service` router** on port `:8080` (with earlier `node-llama-cpp`, vLLM, Kitten, and GPT-SoVITS paths retired):

| Model / Role | Configuration & Purpose |
| --- | --- |
| **`Qwen3.5 9B`** | Primary conversational Persona, multimodal Vision reasoning, and Full Auto high-reasoning activity selection |
| **`Environment 0.8B / 2B`** | Fast Orchestrator (Intent) and Task Decisions specialists served from shared base weights with **per-request LoRA adapters** |
| **`Freestyle Qwen`** | Generates compact joint, foot, and body target programs and event-recovery motions for the 12-servo V2 body |
| **`Qwen3 Embedding 0.6B` & `Nomic Embed v1.5`** | CPU-only embedding models (`--device none`) for episodic memory retrieval and semantic indexing without consuming GPU VRAM |

To preserve workstation and host memory, `llama-cpp.service` runs with `load-on-startup = false` and a **5-minute (`300 s`) idle unload timeout**, loading weights on demand and supports native inference cancellation when a newer priority event preempts an in-flight turn.

## Single `environment-bridge` and `environment-mode.json`

Ainekio connects to MetaHuman OS through a single consolidated **`environment-bridge`** agent with **multi-host following**:

1. **Multi-host connection following**: Whether the robot's `Master/gateway` is running on the local desktop or an offboard **Radxa Dragon Q6A**, `environment-bridge` maintains one authoritative observation and action stream. High-frequency feedback-health updates update live `Robot Status` state directly without spawning redundant conversational turns.
2. **Unified `environment-mode.json` cognitive graph**: Incoming user requests, voice transcripts, camera frames, and action settlements enter a single validated graph.
3. **Clear role separation**:
   - **Orchestrator (Intent)** classifies whether incoming input is a new request, a modification, a cancellation, or a conversational turn, and decides whether an outward spoken reply is needed.
   - **Task Decisions** selects concrete robot actions (`robotCommand`, `locomotionGoal`, `freestyleProgram`, `captureImage`, or specialist delegation) without injecting intermediate filler speech between movements.
   - **Goal Review** evaluates returned action receipts and visual evidence against the active objective.
   - **Standing Persona** (`persona/core.json`) is the single outward voice owner, synthesizing the final conversational response from the completed or in-progress task state.

## Fast Body Events (`fast-body-event-mode.json`)

Physical disturbances require immediate, lightweight reactions rather than full multi-step planning:

- When the `ESP32-P4` detects a physical tip, shake, or servo jam/stall, it emits a body event with live `LSM6DS3` IMU and `CD74HC4067` joint-error telemetry.
- MetaHuman routes tip, shake, and stall events to **`fast-body-event-mode.json`**, a dedicated single-call Lightweight workflow.
- The model emits **`be_` token-matched facial expressions** (mapped directly to the 58 expressions on the 1.9" `ST7789` LCD) paired with a brief, situational remark, without polluting long-term episodic memory or derailing an existing saved execution.
- Boot and wake transitions retain the full contextual workflow so Ainekio can orient itself, check its surroundings, and rise cleanly.

## Durable execution and the Work Coordinator

A robot request often spans multiple physical actions and sensor checks—for example, standing up, turning toward a target, capturing a fresh frame, and verifying arrival.

- **LangGraph + SQLite checkpoints**: Every admitted request runs as a durable **execution** managed by the **Work Coordinator**. The execution's objective, ordered event history, completed node outputs, and pending actions are checkpointed in SQLite.
- **Saved waits**: While the physical robot executes a gait or a specialist worker runs in the background, the execution enters a saved wait rather than holding open a fragile polling loop.
- **Action receipts and epoch correlation**: `Environment Bridge Out` records the intended action before dispatch. The gateway tracks the command across connection epochs until a terminal receipt (`done`, `cancelled`, `nak`, or `outcome_unknown` on unverified disconnect) arrives, preventing accidental duplicate motion after a Wi-Fi drop.
- **Goal-directed locomotion**: Active Task connects model-selected distance, turn, approach, follow, and visual endpoints to measured progress (joint arrival, IMU heading, and OpenGV / MoGe depth odometry) and the gait solver's terminal `Finish` receipt.

## Standing Persona and Desire management

Identity and autonomous motivation have strict ownership boundaries:

- **Standing Persona (`persona/core.json`)**: Represents Ainekio's core identity, values, and voice. Only the **Psychotherapist** agent (during Sleep or explicit review) and manual operator edits may modify `persona/core.json`.
- **Desire Agent**: Manages candidate intentions in Agency, adjusting desire strengths based on attributed memories, standing goals, and real task outcomes, and archiving desires once satisfied or obsolete. Approved desires execute through finite, step-tracked plans (`1–10` steps) rather than acting as unbounded background prompts.

## Big Brother delegation and hosted UI

When a request requires heavy software engineering, repository inspection, or complex host operations beyond the local embedded specialists:

- **Big Brother Terminal (`TerminalChat.svelte`)**: Provides a direct interactive operator and escalation channel inside MetaHuman OS.
- **Asynchronous Computer Tasks (`big-brother-tool-mode.json`)**: Environment workflows can delegate asynchronous computer tasks and run **`system-code-review`** through Big Brother while the robot continues interacting and reporting progress.
- **Hosted Static UI (`https://mh.ainek.io`)**: The MetaHuman OS web interface—covering chat, node editor, Agent Monitor, memory browser, Agency, and Robot Status—is also published as a hosted static UI at [`https://mh.ainek.io`](https://mh.ainek.io) that connects to the operator's active runtime.
