While [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot) contains the `ESP32-P4` C firmware, locomotion training code, and the Python Body Control gateway, the robot's mind lives in its own repository: **[Ainekio OS (`Greg-Aster/ainekio-os`)](https://github.com/Greg-Aster/ainekio-os)** (formerly MetaHuman OS).

Ainekio OS is a **local-first operating system for a persistent personal AI identity**. Instead of wrapping a stateless chat prompt around robot commands, it provides a shared runtime for identity, attributed episodic memory, node-based cognitive workflows, crash-safe SQLite task execution, voice synthesis/recognition, LoRA adapter training, and background reflection—capable of running **standalone on a workstation** or **embodied inside the physical Ainekio V2 quadruped** (and the earlier V1 prototype).

## 1. Standalone vs. embodied roles

Splitting the project across two repositories keeps hard real-time motor loops decoupled from language-model latency and lets Ainekio OS keep running on a desktop, laptop, or edge computer even when no physical robot is switched on:

| System | Repository | Core Responsibilities |
| --- | --- | --- |
| **Ainekio OS (Mind)** | [`Greg-Aster/ainekio-os`](https://github.com/Greg-Aster/ainekio-os) | Standing Persona, local web workbench, CLI, and Android clients, visual cognitive graphs, durable SQLite workflow execution, provenance-tagged episodic memory, background reflection & desire agents, local/hybrid model & voice routing, LoRA training pipelines, and the embodied bridge |
| **Ainekio-bot (Body & Gateway)** | [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot) | `650 g` 12-servo V2 hardware (and 8-servo V1 archive), `ESP32-P4` C firmware (`50 Hz` on-chip MicroDuck neural gait, `CD74HC4067` `C4–C15` → `GPIO49` feedback, `208 Hz` IMU, 59 LCD expressions), Body Control gateway & Cockpit HUD, optical-flow obstacle range, and the 349-motion Freestyle library |

Every client surface—the local Astro/Svelte web workbench (including an interactive system architecture map with read-aloud subsystem tours), the terminal CLI, the Android mobile client, and the embodied robot bridge—talks to a single unified core engine and profile store, with optional AES encryption for personal profile data.

## 2. Standing Persona, cognitive modes, and trust tiers

Because Ainekio OS can operate both as a personal digital counterpart and as a physical robot companion, it separates **who the system is modeling** from **how much autonomy it is granted**.

### Standing Persona

Identity is anchored by a single **Standing Persona** record holding core traits (including Big Five dimensions), values, communication style, and long-term goals. To prevent personality drift or accidental self-modification during everyday conversation, ordinary chat and task workflows treat the Standing Persona as read-only; only the scheduled overnight **Psychotherapist** review (or a direct edit by the human owner) can update it. Short-term intentions and candidate activities live separately in an **Agency / Desire** store where their strengths rise or decay based on real outcomes.

### Four cognitive modes & five trust tiers

| Cognitive Mode | Memory & Learning Behavior | Typical Trust Tier & Role |
| --- | --- | --- |
| **Dual Consciousness** | Full episodic memory writes, proactive background agents, and personalization adapters that learn the *human owner's* voice and thought patterns | `adaptive_auto` — Long-term personal mirror and digital counterpart |
| **Agent Mode** | Task-scoped memory writes; direct engineering and desktop assistant that can delegate heavy coding or terminal jobs | `suggest` — Focused workbench and coding assistant |
| **Emulation Mode** | Read-only memory and frozen persona/adapter state with zero background mutation | `observe` — Safe demonstrations, snapshots, and historical replay |
| **Environment Mode** | Connects multimodal robot observations to bounded physical actions while training Ainekio's *companion* replies and action routing | Paired with **Reactive**, **Semi Mode**, or **Full Auto** ([autonomy guide](/posts/bounded-autonomy/)) across `observe` → `supervised_auto` → `bounded_auto` → `adaptive_auto` |

## 3. Episodic memory & SQLite durable execution

Long-running companions fail in two predictable ways: hallucinated memories get mixed up with real events, and multi-step physical tasks lose their place whenever a movement takes several seconds or Wi-Fi hiccups. Ainekio OS addresses both in storage:

- **Provenance-tagged episodic memory**: Every stored memory carries explicit origin metadata—human chat, room voice transcript, robot camera observation, verified action outcome, internal reflection, or symbolic dream. Semantic search runs on **CPU-only embedding models** (`Qwen3-Embedding-0.6B` and `Nomic-Embed-Text-v1.5`) so vector retrieval never competes with conversational or vision models for GPU VRAM.
- **Crash-safe SQLite durable execution**: Multi-step turns and autonomous goals execute inside a write-ahead-logged SQLite state machine with leased coordinator ownership and content-addressed image/payload blobs. When Ainekio starts walking across a room, requests a camera snapshot, or delegates a coding job, the workflow writes a durable event checkpoint (`waitForEvent`) instead of holding open a fragile in-memory timer. If a process restarts, recovery reconciles sequence receipts so physical robot motions are **never replayed twice**.

## 4. Node-based cognitive graphs

Rather than burying prompt chains inside imperative server code, conversational turns, robot reflexes, curiosity loops, desire planners, and sleep stages are defined as **47 inspectable node-based cognitive graphs** that can be viewed and edited live in the local web workbench.

Graphs support conditional edge predicates, activation guards, bounded iteration loops, nested sub-workflows, and durable event suspension across seven functional groups:

1. **Interactive Modes**: Top-level workflows for Dual Consciousness, Agent, Emulation, and Embodied Environment turns.
2. **Robot Embodiment & Reflexes**: Intent routing, active robot task loops, locomotion goal review, wake-up orientation, varied fast body-contact reflexes, speech pacing, and training-example curation ([embodied bridge guide](/posts/metahuman-integration/)).
3. **Embodied Boredom & Initiative**: Camera observation, Freestyle leg-stretching, and reflection workflows triggered when internal drives cross threshold in Semi or Full Auto mode.
4. **Inner Life, Curiosity & Dreams**: Associative train-of-thought chains, self-directed Q&A curiosity, background reflection, daydreaming, and overnight symbolic dreaming.
5. **Desire Lifecycle**: Generating, planning (`1–10` finite steps), reviewing, executing, and scoring autonomous intentions.
6. **Memory Curation & Therapy**: Tagging raw memories, curating supervised training pairs, mood/goal review, and Psychotherapist persona evaluation.
7. **Onboarding & Coding Escalation**: Guided persona interviews, asynchronous coding/terminal delegation, and automated repository code review.

## 5. Local & hybrid model and voice routing

Instead of binding the entire operating system to one monolithic model, Ainekio OS assigns **12 specialist cognitive roles**—including intent orchestration, robot action selection, vision grounding, outward persona speech, fast body-event reflexes, memory curation, planning, coding, psychotherapy, and embeddings—independently across local, LAN, and optional cloud backends:

- **Local `llama.cpp` & Ollama inference**: In pure local mode, a shared `llama.cpp` router (or Ollama) serves a primary multimodal model (`Qwen3.5 9B` for persona conversation, vision grounding, and high-reasoning autonomy) alongside lightweight `0.8B` and `2B` specialist **LoRA adapters** swapped per request for fast intent classification, robot task selection, and **Freestyle** motion synthesis (**489-row** dataset: **73** curated library motions + **416** fault-recovery trajectories). Idle model weights unload automatically after five minutes of inactivity, and in-flight generations cancel immediately if a higher-priority human turn arrives.
- **LAN-shared edge compute**: When the robot gateway runs on a compact SBC such as a `Radxa Dragon Q6A`, it can keep sub-100 ms intent routing local or point heavy vision and speech roles at a desktop GPU workstation on the same LAN.
- **Voice pipeline (`Whisper` STT + `Kokoro` / `Piper` TTS)**: Speech-to-text (**Whisper**) and expressive text-to-speech (**Kokoro** with custom voicepacks) can each switch live between local GPU/CPU execution and a remote LAN workstation, backed by a fast local **Piper ONNX** voice fallback when GPU servers are offline ([voice loop guide](/posts/voice-loop/)).
- **Optional "Big Brother" coding delegates**: For heavy software debugging, repository analysis, or desktop terminal workflows that exceed small local models, Ainekio OS can escalate tasks to persistent CLI coding sessions (**Codex**, **Claude Code**, or warm **Gemini** sessions) while keeping the Standing Persona in charge of conversation.

## 6. The nightly `02:00` consolidation sleep cycle

Inside a configurable overnight window (defaulting to **`02:00 AM`**), Ainekio OS pauses autonomous robot motion and runs an **8-stage software sleep cycle**—waking immediately and cancelling remaining stages if someone speaks to it:

1. **Organize Memories**: Enriches the day's raw episodic turns and observations with entities and semantic tags.
2. **Curate Dialogue**: Distills clean conversational training pairs while filtering out transient command noise.
3. **Curate Robot Decisions**: Surfaces candidate `0.8B / 2B` action-routing examples from real physical robot runs for human review.
4. **Fit Personalization Adapters**: Trains candidate LoRA weights on reviewed interaction history.
5. **Update Desires**: Adjusts autonomous desire strengths across `[0, 1]` from actual outcomes, archives completed desires, and drafts bounded `1–10` step plans.
6. **Dream**: Samples **15 lifetime memories** along a **227-day decay curve** into symbolic dreams and nightmares, stored with explicit `dream` provenance so imagined scenes are never mistaken for real room events.
7. **Psychotherapist Persona Review**: Conducts reflective interviewing over recent experiences and dreams to make careful, auditable adjustments to the Standing Persona.
8. **Rebuild Vector Index**: Refreshes CPU embeddings across the consolidated memory store for the next day.
