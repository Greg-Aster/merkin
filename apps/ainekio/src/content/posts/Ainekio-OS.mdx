While [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot) owns the 3D-printed 12-servo V2 quadruped hardware, `ESP32-P4` C firmware, MuJoCo/MJX reinforcement learning, and the Python **Body Control** gateway, the companion's mind lives in a separate, standalone operating system: **[Ainekio OS (`Greg-Aster/ainekio-os`)](https://github.com/Greg-Aster/ainekio-os)**.

Publicly rebranded to **Ainekio OS** in November 2026 (`2dc83693`, while retaining internal `@metahuman/*` workspace package names and the `mh` CLI), Ainekio OS is a **local-first operating system for a persistent personal AI identity**. Rather than acting as a stateless chatbot wrapper or a robot-only script, it combines a web workbench, terminal CLI, Android client, attributed episodic memory, 47 node-based cognitive graphs, durable SQLite execution, autonomous background agents, voice servers, LoRA training pipelines, and **Big Brother** CLI escalation—capable of running either **standalone as a digital counterpart** or **embodied inside the physical Ainekio V2 robot**.

## 1. Two repositories, clear ownership boundaries

Splitting the project across two repositories keeps real-time motor loops decoupled from long-horizon reasoning and allows Ainekio OS to run on a desktop workstation, laptop, or edge computer even when no physical robot is powered on:

| System Layer | Canonical Repository | Primary Responsibilities |
| --- | --- | --- |
| **Ainekio OS (Mind & Personal AI OS)** | [`Greg-Aster/ainekio-os`](https://github.com/Greg-Aster/ainekio-os) | Persistent `Standing Persona` (`persona/core.json`), Web/CLI/Android interfaces, **47 cognitive graphs**, **14-table SQLite durable execution**, episodic memory & CPU vector search, **24 background agents**, **8-stage `02:00` Sleep Cycle**, **12 specialist model roles** (`ServerStatus`), Whisper/Kokoro/Piper voice orchestration, LoRA training, Big Brother CLI escalation, and `Environment Bridge`. |
| **Ainekio-bot (Body, Firmware & Gait)** | [`Greg-Aster/Ainekio-bot`](https://github.com/Greg-Aster/Ainekio-bot) | `650 g` 12-servo V2 hardware & Blender/MJCF CAD (plus V1 8-servo archive), `ESP32-P4` C firmware (`0.8.159-p4-microduck-v17` with **on-chip `50 Hz` L2-cached MicroDuck neural gait**, 4th-wire `CD74HC4067` feedback, `208 Hz` `LSM6DS3` IMU, 59 `ST7789` LCD expressions), **Body Control** Python gateway & **Cockpit HUD** (`:8790` / `:8791`), optical-flow contact range, and **Freestyle** (`489` training rows). |

## 2. Monorepo structure & client surfaces

Ainekio OS is organized as a `pnpm` TypeScript monorepo (`Node >=22.3`) where every user surface speaks to one canonical API router:

- **`packages/core` (`@metahuman/core`)**: The single canonical engine owning authentication, optional AES-encrypted profile storage (`profiles/<username>/`), `UnifiedQueueManager` (**Work Coordinator**), `ExecutionStore` (`executions.sqlite`), the **Cognitive Graph Executor** (`graph-executor.ts` + **176 `.node.ts` files across 24 node categories**), the Model Router/Registry, Voice/TTS delivery queues, Terminal/Big Brother runtime, and **123 unified HTTP/SSE API handler modules** (`src/api/router.ts`).
- **`apps/site` (`metahuman-site`)**: Astro 5 + Svelte 5 + Tailwind + `@xyflow/svelte` web workbench. In `2dc83693`, over 150 per-route forwarding files were replaced by a single 3-line catch-all adapter (`src/pages/api/[...path].ts`) delegating directly to `@metahuman/core`. Supports atomic server release builds (`build-release.mjs`) as well as static hosted builds ([`https://mh.ainek.io`](https://mh.ainek.io)) that connect to a local or remote Ainekio OS node.
- **Interactive System Map (`/architecture`)**: A live collapsible `@xyflow/svelte` architecture canvas (`apps/site/src/pages/architecture.astro`) visualizing data flow across human inputs, Core subsystems, Brain services, Body Control, and inference backends, complete with **TTS Read-Aloud** subsystem walkthroughs.
- **`packages/cli` (`metahuman-cli`) & `apps/react-native`**: The **`mh`** command-line interface (`mh start`, `mh status`, `mh chat`, `mh task`, `mh trust`, `mh persona`, `mh agent`, `mh big-brother`, `mh voice-server`) and the maintained **Android React Native** mobile shell sharing Core's HTTP router and cognitive graphs.
- **`brain/` (`@metahuman/brain`)**: Background cognitive metabolism housing **24 autonomous agent workers**, persistent services (`maintenance-service`, `terminal`, `environment-bridge`, `active-operator`), and GGUF LoRA training pipelines (`environment-action-selector` for `0.8B/2B` Intent/Task specialists and `personalization` for profile adapters).

## 3. Orthogonal operating modes & five trust tiers

Because Ainekio OS serves both as a personal digital counterpart and as an embodied quadruped brain, it separates **who the AI is modeling** (Cognitive Mode) from **how proactively a connected robot acts** (Robot Autonomy Mode), governed by explicit **Trust Levels** (`observe`, `suggest`, `supervised_auto`, `bounded_auto`, `adaptive_auto`):

| Cognitive Mode | Memory & Training Posture | Default Trust Coupling & Purpose |
| --- | --- | --- |
| **Dual Consciousness (`dual`)** | Full episodic memory writes; proactive background agents; personalization LoRA learns the *human operator's* voice and reasoning patterns. | `adaptive_auto` — Digital counterpart and long-term personal mirror. |
| **Agent Mode (`agent`)** | Command-scoped memory writes; direct task assistant escalating coding and host operations to Big Brother. | `suggest` — Focused engineering and desktop automation assistant. |
| **Emulation Mode (`emulation`)** | Read-only derived memory; freezes `persona/core.json` and adapter state with zero background mutation. | `observe` — Safe demonstration, snapshotting, and historical replay. |
| **Environment Mode (`environment`)** | Bridges multimodal robot observations and verified physical actions; conversational training learns *Ainekio's companion* replies. | Paired with **Reactive**, **Semi-Autonomous** (`5 min` signed drive deltas), or **Fully Autonomous** (continuous high-reasoning loop). |

## 4. Cognitive Graph Engine & all 47 built-in workflows

Instead of hardcoding prompt chains in imperative TypeScript, every conversational turn, physical reflex, curiosity loop, desire plan, and sleep stage runs as an inspectable JSON graph in `etc/cognitive-graphs/` executed under **Scheduler Contract v1** (`graph-executor.ts`) and editable live in the `@xyflow/svelte` **Cognitive Workflow Editor**:

- **Deterministic graph semantics**: Explicit `sourceHandle` routing, conditional edge predicates (`data.when`), node activation guards (`activation.when`), control-only dependency edges (`data.kind: "control"`), bounded iteration loops (`maxLoopIterations`), nested `workflow-call` subgraphs, and LangGraph-backed durable suspension (`waitForEvent`).
- **47 built-in cognitive graphs across 7 functional families**:
  1. **Interactive Modes (4)**: `dual-mode`, `agent-mode`, `emulation-mode`, `environment-mode`.
  2. **Robot Embodiment, Tasks & Reflexes (12)**: `environment-conversation-mode`, `robot-active-task-mode`, `robot-autonomy-controller-mode`, `robot-goal-review-mode`, `robot-status-mode`, `robot-wake-up-mode`, `fast-body-event-mode`, `body-event-trigger-mode`, `robot-speech-mode`, `robot-display-feedback-mode`, `robot-buffer-admission`, `environment-training-curator-mode`.
  3. **Embodied Boredom & Initiative (3)**: `boredom-observer-mode`, `boredom-movement-mode`, `boredom-reflection-mode`.
  4. **Inner Life, Existential Curiosity & Dreams (7)**: `reflector-mode`, `dreamer-mode`, `daydreamer-mode`, `curiosity-mode`, `curiosity-researcher`, `inner-curiosity`, `train-of-thought`.
  5. **Agency & Desire Lifecycle (6)**: `desire-generator`, `desire-planner`, `desire-reviewer`, `desire-executor`, `desire-outcome-reviewer`, `desire-checkin`.
  6. **Persona, Memory Curation & Therapy (6)**: `organizer-agent`, `audio-organizer`, `curator-mode`, `psychoanalyzer`, `mood-review`, `goal-review`.
  7. **Onboarding, Big Brother & Self-Healing (9)**: `persona-interview-question`, `persona-extraction`, `big-brother-response-mode`, `big-brother-tool-mode`, `system-code-review-mode`, `self-healing-analysis`, `response-pipeline`, `semantic-turn`, `system-event`.

## 5. `ServerStatus` compute plane, 12 specialist roles & hybrid inference

Commit `96e74c01` consolidated all LLM, LoRA, CLI escalation, and voice routing controls into the right-drawer **`ServerStatus`** control plane (`ServerStatus.svelte`), routing **12 specialist cognitive roles** independently across local, remote-LAN, and cloud/CLI providers:

1. **12 Specialist Roles**: `orchestrator` (Intent), `environmentActionSelector` (Task Decisions), `environmentVision`, `persona`, `autonomy`, `lightweight` (Fast Body Events), `curator`, `coder`, `planner`, `summarizer`, `psychotherapist`, and `embedder`.
2. **One-Click Routing Presets**:
   - **`Local`**: Runs every role locally through the shared **`llama-cpp.service`** router (`:8080`, `load-on-startup = false`, 5-minute idle weight eviction, custom `shared-host-kv.patch` cancellation, and `json-schema-number-sign.patch`), sharing a single base model in VRAM across per-request `0.8B/2B` GGUF LoRA adapters while keeping `Qwen3-Embedding-0.6B` (`1024D`) / `Nomic-Embed-Text-v1.5` (`768D`) on CPU (`--device none`).
   - **`Hybrid`**: Keeps sub-100 ms edge action routing (`orchestrator`, `environmentActionSelector`) on local `0.8B` LoRA specialists while routing heavy multimodal and reflective roles (`persona`, `environmentVision`, `autonomy`, `lightweight`) to the warm `GeminiAcpServer` daemon or a connected desktop server.
   - **`BB-Codex` & `BB-Gemini`**: Routes high-reasoning roles through persistent Big Brother sessions.
3. **Remote `llama.cpp` & Toggleable CUDA Voice Servers**:
   - An edge host (such as a **Radxa Dragon Q6A**) can discover and assign `remote-server:remote-llama-cpp-*` models exposed by a workstation Ainekio OS instance.
   - **Whisper STT (`:9883`)** and **Kokoro TTS (`:9882`)** each support live **`local` ↔ `remote`** target switching (`POST action: "set-target"`), automatically stopping local GPU/CPU processes when pointed at a remote host, paired with a fast local **Piper ONNX** TTS fallback and ordered speech chunk delivery (`delivery-queue.ts`). (Legacy RVC and `voice-training.ts` paths were retired in `2dc83693`.)
4. **Big Brother CLI & Warm `GeminiAcpServer` Pool**:
   - Supports **`codex`** (native app-server), **`claude-code`**, and **`gemini`** as first-class Big Brother CLI providers, plus direct multimodal REST routing (`gemini`, `claude`, `openrouter`).
   - `TerminalRuntime` maintains a persistent **`GeminiAcpServer`** (`agy acp` over JSON-RPC stdio in an isolated profile home) with a **warm pool of 2 pre-initialized sessions** (`WARM_SESSION_POOL_SIZE = 2`), eliminating CLI cold-start overhead for sub-second multimodal text+image turns.

## 6. Durable SQLite execution, Inner Life & the `02:00` Sleep Cycle

### Crash-safe `executions.sqlite` (14 tables)

Every multi-step request or autonomous activity runs inside per-profile `executions.sqlite` (WAL mode) backed by **14 relational tables**, SHA-256 content-addressed image/payload blobs, leased `Work Coordinator` ownership, and `currentTask` vs. `parkedGoals` (`idle` executions awaiting user or autonomy input). When the robot waits for a gait, camera snapshot, or Big Brother job, `waitForEvent` persists an event checkpoint rather than holding open a fragile in-memory promise—and crash recovery reconciles sequence receipts so physical robot movements are **never replayed twice**.

Even rapid physical reflexes leverage this ledger: when V2 is tipped, shaken, or hits a servo stall, **`fast-body-event-mode.json`** queries the last **6 durable `fast_body_event_response` entries** (`recentReactionLimit = 6`, `temperature = 0.8`, `repeatPenalty = 1.2`) so Ainekio pairs its `be_` `ST7789` facial expression with fresh dry wit rather than repeating the same canned exclamation.

### 8-stage `02:00 AM` software Sleep Workflow

Inside the nightly `23:00–06:30` window (`etc/sleep.json`, default trigger **`02:00`**), Ainekio OS pauses autonomous movement and runs an 8-stage cognitive maintenance pipeline (`sleep-workflow.ts`)—waking cleanly and cancelling remaining stages immediately if a human speaks or interacts:

1. **`organize-memory` (`Organizer`)**: Enriches raw episodic memories (both human turns and Ainekio's attributed replies under `indexContentMode: "all"`) with entities and semantic tags.
2. **`curate-memory` (`Curator`)**: Distills clean supervised conversational pairs while filtering out transient system noise.
3. **`curate-environment-decisions` (`Environment Training Curator`)**: Surfaces candidate `0.8B/2B` Intent and Task LoRA training examples from real robot runs for operator review.
4. **`train-personalization` (`Personalization Trainer`)**: Fits candidate profile LoRA weights on curated history.
5. **`run-desire-agent` (`Desire Agent`)**: Updates autonomous desire strengths across `[0, 1]`, archives zero-strength desires, and formulates finite `1–10` step plans.
6. **`dream` (`Dreamer`)**: Samples 15 lifetime memories along a `227-day` decay curve into symbolic dreams and nightmares stored with explicit `dream` provenance so imagined scenes are never mistaken for physical events.
7. **`review-persona` (`Psychotherapist`)**: Runs `psychoanalyzer.json`—the **sole autonomous agent authorized to edit `persona/core.json`**—conducting motivational interviewing over recent memories and dreams to evolve long-term traits and goals safely.
8. **`rebuild-index` (`Refresh Memory Index`)**: Reconciles CPU vector embeddings across the updated memory store.
