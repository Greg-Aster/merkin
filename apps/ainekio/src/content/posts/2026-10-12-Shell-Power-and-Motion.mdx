## Lift each foot before lowering: smoother Lay Down and Play Dead

**Lay Down** and **Play Dead** now perform individual **8 mm lift-and-place steps**
(0.8 s per foot) before the 2.0 s body-lowering ramp, keeping the 7.0 s authored
duration while cutting peak joint angular velocity nearly in half:

| Metric | Lay Down (previous → revised) | Play Dead (previous → revised) |
| --- | --- | --- |
| Authored duration | 7.0 s → 7.0 s | 7.0 s → 7.0 s |
| Peak joint speed | **216.36 → 137.59°/s** | **308.62 → 156.16°/s** |
| Lowest modeled sole height | −0.067 → ~0.0 mm | −0.240 → ~0.0 mm |
| Minimum modeled body clearance | 0.15 mm | 0.15 mm |

When exiting a grounded posture, the P4 controller retraces the grounded clip in
reverse with a short alignment segment before entering the next named motion.
See the [before/after validation JSON](/posts/2026-10-12-progress/motion-comparison.json)
and the [gait development log](/posts/gait-development/).

## YOLOE: open-vocabulary search and visual target tracking

Perception has moved beyond the fixed person-only detector to an open-vocabulary
pipeline combining **YOLOE-26n-seg**, **MobileCLIP2-B** text embeddings, and
**ByteTrack** multi-frame track association.

  <img src="/posts/2026-10-12-progress/vision-flow.svg" alt="Diagram of P4 camera frames entering the gateway YOLOE and ByteTrack worker, then the Body Control display and MetaHuman task workflow; target selection returns with the original image identity" width="1000" height="660" loading="lazy" />

| Capability | Earlier detector | YOLOE + ByteTrack pipeline |
| --- | --- | --- |
| Default vocabulary | Fixed person-only YOLO checkpoint | Prepared YOLOE person prompt vocabulary |
| Open-vocabulary text search | Not supported | Search any named category using local MobileCLIP2-B text embeddings |
| Visual region selection | Not supported | Submit a bounding box together with the exact reference JPEG (`gateway/robot/session/frame` identity) |
| Multi-frame continuity | Single-frame detections | Persistent track IDs across frames via ByteTrack |
| Release to default | Not supported | Clear target selection and restore default person tracking |

### Live P4 camera-to-MetaHuman chair tracking trial

On October 12, we tested the full P4 camera → gateway → MetaHuman bridge path against
a physical chair in the room:

1. **Live person & category search:** Real P4 camera frames streamed into MetaHuman
   with person track IDs, and a text search for `"chair"` returned chair detections
   tagged with the query ID and track ID.
2. **Visual prompt specificity:** An initial coarse region proposed by CPU Qwen 0.8B
   (10.2 s inference) was too wide to hold a track across 13 frames, whereas a tight
   bounding box on the same reference JPEG locked onto the chair across **all 8
   subsequent frames** with a single consistent track ID (confidence scores `0.37–0.65`).
3. **Model Router vision role:** `Environment vision` now routes through the Model
   Router so image queries always hit a vision-capable model rather than falling back
   to a text-only adapter.

## Trained Qwen3.5 0.8B Intent and Task specialists

Extending the [October 8 task/conversation split](/posts/2026-10-08-standing-walking/),
the **Intent orchestrator** and **Task manager** now run independent LoRA adapters on
**Qwen3.5 0.8B**, trained on synthetic capability catalogs with reordered commands,
opaque identifiers, conditional requests, and compound goals.

<figure>
  <img src="/posts/2026-10-12-progress/specialist-results.svg" alt="Diagram showing the intent orchestrator selecting task, conversation and computer-tool routes while existing execution and gateway owners retain body control" width="1000" height="660" loading="lazy" />
  <figcaption>Intent orchestrator, Task specialist, Conversation, Computer-task delegation, and Body Control execution boundaries.</figcaption>

- **Intent routing (`009` → `010`):** On the 200-request expanded evaluation benchmark,
  acceptable routing jumped from **60/200 to 185/200** at a **100 ms median latency**
  (outperforming a parallel Speck2 experiment at 173/200).
- **Computer-task delegation & live Robot Status:** Intent can now route file,
  research, or software jobs to the Terminal/Codex integration via Work Coordinator
  ([`8b398f0d`](https://github.com/Greg-Aster/ainekio-os/commit/8b398f0d)), while
  `Robot Status` ([`7450eeba`](https://github.com/Greg-Aster/ainekio-os/commit/7450eeba))
  distinguishes fresh, stale, disabled, and disconnected recognition states.

### Why we rejected a higher-scoring Task candidate

A subsequent goal-planning Task candidate improved overall evaluation matches from
67.9% to 78.6%, but regressed on previously passing regression cases and introduced
more unintended physical movements on conversational turns:

| Benchmark metric | Retained `010` Task adapter | Rejected goal candidate |
| --- | ---: | ---: |
| Evaluation reference matches | 159 / 234 (67.9%) | 184 / 234 (78.6%) |
| Regression reference matches | **93 / 138 (67.4%)** | 90 / 138 (65.2%) |
| Unintended physical actions (evaluation) | 21 | 12 |
| Unintended physical actions (regression) | **15** | 20 |
| Median serving latency | 489 ms | 484 ms |
| Contract/schema validity | 100% (234/234 & 138/138) | 100% (234/234 & 138/138) |

Keeping the regression gate strict prevented promoting an adapter that moved the robot
during conversation-only turns. Download the
[comparison metrics JSON](/posts/2026-10-12-progress/task-model-comparison.json) for
the full breakdown.
