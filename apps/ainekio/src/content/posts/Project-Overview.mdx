# Ainekio at a glance

Ainekio is a small, owner-built robot familiar connected to MetaHuman OS. It
combines a four-legged body with a camera, microphone, speaker, and OLED face.
MetaHuman handles conversation and reasoning; the robot controller handles
movement and local safety.

The working V1 uses eight servos and an ESP32-S3. V2 is planned around twelve
MG90S-class servos, a new chassis, and an ESP32-P4 controller. Its first movement
system will use scripted poses and sequences.

MetaHuman is also being redesigned to save an objective and its progress across
waits, specialist work, user corrections, and restarts. That software is under
integration. The new body and the deployed system still need testing.

## What is being built

- **V2 body:** three joints per leg, experimental leg prints, a serviceable
  chassis, and a power supply sized from measured loads. Start with the
  [V2 roadmap](/posts/ainekio-v2/).
- **MetaHuman integration:** saved workflows, action records, and recovery that
  keep track of what the robot was asked to do and what happened. Read
  [how the integration works](/posts/metahuman-integration/).

The [dated status report](/posts/current-status/) records the current code,
reported test results, and remaining work. V1 motion and audio tests establish
the starting point; V2 must pass its own tests.

## How a request reaches the robot

1. MetaHuman's Work Coordinator accepts the request. A saved workflow retains
   the objective and selects an action the connected robot supports.
2. The Environment Bridge sends it through Ainekio's adapter and authenticated
   gateway.
3. The body controller checks the command, applies motion limits, and executes it.
4. Results and observations return to the saved workflow. MetaHuman reviews
   whether the objective is complete or needs another step.

A command finishing and a goal being met can be different things. Walking can
finish successfully while a goal such as finding better light still needs a
new camera image. Robot Status displays the workflow's progress.

## Where the work lives

The [Ainekio repository](https://github.com/Greg-Aster/Ainekio-bot) contains
hardware designs, the shared body core, firmware, protocol, motion assets,
gateway, dashboard, and Environment adapter. The simulator experiment has
been retired; its [July notes](/posts/archive/motion-systems/) remain as history.

[MetaHuman OS](https://github.com/Greg-Aster/metahuman-os) provides persona and
memory, conversation, models, speech services, work scheduling, saved graph
execution, and autonomy policy. Optional Desire work uses the same Work
Coordinator to submit jobs.

V1's mechanics began with [Sesame](https://github.com/dorianborian/sesame-robot).
V2 evaluates OpenHarmony Puppy V2 leg geometry with Ainekio's own chassis and
software. The site's current illustrations show a prospective V2 hybrid with
a stout body and serrated red legs. The comparison image retains V1 alongside
that concept; final mechanics and electronics depend on testing.
