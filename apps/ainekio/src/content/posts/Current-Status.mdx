# September 7 snapshot

Ainekio's working body has eight MG90S servos and an ESP32-S3 controller. V2 is
planned with twelve servos and an ESP32-P4. Experimental leg work has
started; the complete body and P4 firmware remain ahead.

MetaHuman's development code now includes persistent graph execution, saved
waits, child-workflow returns, and recovery. Ainekio's adapter is being updated
to retain action records across interruptions. Focused tests have passed, but
the revised system has not completed deployment or physical testing.

*The cover compares V1 with a V2 concept illustration. See the
[V2 roadmap](/posts/ainekio-v2/) for the actual design work.*

`Frame8` Blender and STL files are now tracked, correcting the August report.
They belong to V1 enclosure history; their presence does not identify the
installed enclosure. The local `12servo/` files are separate V2 design work.

## Software

- **Execution:** SQLite records and LangGraph scheduling retain outputs, event
  waits, child returns, retries, and recovery state.
- **Autonomy:** Full mode continues an eligible saved execution or starts a
  Robot Autonomy Controller when none is active. It can choose speech,
  specialist work, or a robot objective. This replaces the earlier description
  of Full as a rotation among boredom workflows.
- **Robot Status:** displays execution decisions and current facts. The saved
  execution retains the objective.
- **Adapter:** local work adds persistent action IDs, dispatch records, feedback
  redelivery, cancellation, and rejection of stale controllers. If a command
  may have run but its result is missing, recovery must retain that uncertainty.
- **Voice and vision:** S3 capture and playback paths exist. MetaHuman changes
  link utterances, images, and playback results to their originating actions.
  Repeated conversations and camera-based goals still need live testing.

**Simulator:** the experiment was unsuccessful and has been completely
retired. It is outside the current system and V2 plan. The
[July article](/posts/archive/motion-systems/) preserves its history.

## Next tests

1. **One leg:** check fit, horn alignment, travel, stiffness, backlash, bearing
   support, weight, and reachable foot positions.
2. **Power:** measure V1 startup, standing, walking, and demanding normal motion,
   including voltage and temperature.
3. **P4:** validate signals, calibration, and peripherals; progress through one
   loaded leg, two legs, and the complete servo set.
4. **Chassis and motion:** verify clearance, power distribution, and service
   access. Test standing, sitting, walking, turning, and stopping without
   brownouts, binding, or routine near-stall loads.
5. **Integrated software:** finish migration checks, deploy the services, and
   repeat a complete request through dispatch, feedback, observation, and review.
   Include interruption, restart, cancellation, and direct stop. Visual goals
   need images showing the result; speech needs actual playback feedback.
