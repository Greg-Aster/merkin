# When the robot acts on its own

MetaHuman has three autonomy modes. They control when Robot Operator can start
work or resume an eligible saved workflow. Once an objective starts, its progress
is retained through actions, specialist results, user corrections, and waits.

This page describes the September 7 development code. The revised system still
needs deployment and repeated real-robot tests.

## Modes

| Mode | Behavior |
| --- | --- |
| Reactive | Responds to user interaction; Robot Operator stays dormant |
| Semi | Uses configured timing and idle conditions to start finite work or resume an eligible saved wait |
| Full | Responds to Coordinator state, resumes an eligible saved wait, or starts a Robot Autonomy Controller when no execution is active |

Full mode no longer rotates through Boredom Observer, Movement, and Reflection.
Those configured workflows remain available, but a controller uses current
context to choose the next activity.

## Choosing work

The Robot Autonomy Controller receives persona, recent conversation including
the latest user turn, inner dialogue, robot results, Bridge facts, Robot Status,
optional desires, and the Agent Catalog. It can choose speech, an available
finite agent, or a high-level robot objective.

Robot Operator handles timing and permission to start work. Environment
workflows select actions, and the body checks movement. Optional Desire work
is submitted through the Desire Agent and Work Coordinator.

```text
Robot Operator -> Work Coordinator -> Autonomy Controller
  -> speech, specialist work, or robot objective
  -> saved wait -> result -> Goal Review
  -> finish or continue
```

A specialist returning or the robot speaking does not automatically close an
unfinished objective. The workflow records that decision explicitly.

## Progress, correction, and stop

Robot Status displays current facts and workflow decisions. The saved execution
retains the objective, evidence, and pending work for recovery. This replaces
the older Task State continuation design and plans for a separate Robot Status
workflow. Goal Review continues within the execution rather than through an
independent polling loop or a new graph for every result.

Users can steer or cancel work. Mode eligibility, authorization, Sleep state,
job scheduling, and current control of the body constrain autonomous actions.
Robot Operator stays dormant in Reactive mode and during Sleep.

Emergency stop has a direct path that does not depend on model interpretation.
Coordinator and adapter changes coordinate cancellation with body ownership.
An uncertain physical result must be resolved before assuming the body is free
for another attempt. Software cancellation tests still need physical stop
measurements.

## Recorded results

Earlier V1 tests recorded an autonomous movement reaching `done`, an observation
request expiring, and an invalid motion plan being rejected. Those runs used
the previous runtime.

The September review records controlled tests for specialist returns, continued
Goal Review, steering, cancellation, and fresh-process resumption. Live models
and physical autonomy require separate testing. Exact reported counts are in
[Current Status](/posts/current-status/).

## Next demonstration

Repeat one objective through scheduling, model decision, dispatch, robot result,
fresh observation, and review. Exercise continuation, specialist returns, stop,
user correction, Sleep, Reactive mode, disconnect, and restart.

The response should match the result: report rejected actions as rejected, retain
uncertain outcomes, and use a fresh image for a visual goal such as finding better
light. These requirements apply to V1 and the planned
[V2 body](/posts/ainekio-v2/).
