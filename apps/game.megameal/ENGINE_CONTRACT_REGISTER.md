# Engine Contract Register

Status: current framework register
Last verified: 2026-06-06

This file is the single ownership map for `apps/game.megameal` engine contracts. It maps the contracts from `GAME_ENGINE_DESIGN_DOCUMENT.md` and `docs/GAME_ENGINE_MIGRATION_PLAN.md` to their current owners, writers, consumers, validation, and forbidden shortcuts.

Before changing a runtime, data, adapter, authoring, or validation contract, update the matching row here. If no row exists, add one before editing implementation. The goal is one source of truth per behavior, explicit consumers, repeatable validation, and no hidden runtime repair.

## Change Rule

Contract changes must be staged in this order:

1. Update the source-of-truth type, schema, or manifest.
2. Update the narrow runtime system or adapter that consumes it.
3. Update any game/content definitions using it.
4. Update durable validation: schemas, audits, or focused tests only when a reusable test owner exists.
5. Delete superseded compatibility code or record a removal condition.

Do not add fallback behavior as a substitute for moving the contract.

## Data Contract Module Ownership

The data-layer contracts are split into focused modules with small public
barrels. The `index.ts` files under `src/engine/data/schemas`,
`src/engine/data/contentGraph`, `src/engine/data/collisionCook`, and
`src/engine/data/terrainCook` are API surfaces only. They must preserve
documented public exports, but contract logic belongs in the focused owner
modules:

- `schemas`: type definitions, asset/level/component/render-profile/runtime
  scene/terrain-package schema validation, shared helpers, and validation
  errors.
- `contentGraph`: runtime scene requirement derivation and generated GLB import
  parity validation.
- `collisionCook`: collision draft validation, dev-preview message validation,
  cook plan/bake output creation, runtime-scene checks, and write-plan
  serialization.
- `terrainCook`: terrain cook manifest validation, shape validation,
  deterministic stable-value hashing, visual/collision/material chunk package
  planning, terrain plan/write-plan creation, generated runtime module
  serialization, and runtime-scene/drift checks.

Do not grow these barrels back into implementation files. New data contract
behavior must go into the narrow owner module and update the matching contract
row below.

## Debt Rules

Compatibility code is allowed only when this file records:

- owner,
- reason,
- affected files,
- validation that prevents spread,
- removal condition.

If those fields are missing, the compatibility code is technical debt and should not be accepted.

## Current Validation Gate

`test:contracts` is the aggregate handoff command for focused contract scripts,
including content/runtime validation and cook/drift checks. It is intentionally
not part of `build`, so production builds stay focused on type checking, drift
checks, and Astro output.

```bash
pnpm --dir apps/game.megameal lint
pnpm --dir apps/game.megameal test:contracts
pnpm --dir apps/game.megameal audit:engine-boundaries
pnpm --dir apps/game.megameal type-check
pnpm --dir apps/game.megameal build
pnpm audit:legacy-game-references
git diff --check -- apps/game.megameal pnpm-lock.yaml
```
