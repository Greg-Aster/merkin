# Engine Contract Register

Status: current framework register
Last verified: 2026-06-06

This file is the single ownership map for `apps/game.megameal` engine contracts. It maps the contracts from `GAME_ENGINE_DESIGN_DOCUMENT.md` and `docs/GAME_ENGINE_MIGRATION_PLAN.md` to their current owners, writers, consumers, validation, and forbidden shortcuts.

Before changing a runtime, data, adapter, authoring, or validation contract, update the matching row here. If no row exists, add one before editing implementation. The goal is one source of truth per behavior, explicit consumers, repeatable validation, and no hidden runtime repair.

## Change Rule

Contract changes must be staged in this order:

1. Update the source-of-truth type, schema, or manifest.
2. Update the narrow runtime system or adapter that consumes it.
3. Update any game/content definitions using it.
4. Update durable validation: schemas, audits, or focused tests only when a reusable test owner exists.
5. Delete superseded compatibility code or record a removal condition.

Do not add fallback behavior as a substitute for moving the contract.

## Open Content And Scale Contracts

These are not blockers for the current playable framework, but they need owner decisions before larger content migration:

- Expanded authored GLB/gltf model library and compressed texture/mesh pipeline.
- Material texture/shader authoring, import, and generation beyond the checked-in Miranda primitive material parameter slice.
- Authored spatial listener/emitter sync, expanded audio library migration, music crossfades, held-charge procedural audio, and durable audio manifest import/generation beyond the current curated track/SFX foundation.
- Durable runtime scene manifest import/generation and physics-body readiness refinement.
- Area/spot light migration, light shadows, runtime point-light budgets, and editor light tooling beyond the authored point-light foundation.
- Reusable water surface assets/prefabs, water quality tiers, reflections/refraction, water volumes, rising water, buoyancy, and durable water-body import/cook tooling through `WaterSurfaceContract`; the first tracked plan is `docs/WATER_SURFACE_SYSTEM_PLAN.md`.
- Environment editor/import controls, generated/cooked environment pipelines, richer reflection-probe blending/debugging, fog/cloud/weather integration, and environment quality tiers building on the manifest-backed `SkyboxEnvironmentContract`; planned packets are tracked in `docs/SKYBOX_FUTURE_FEATURES_IMPLEMENTATION_PLAN.md`.
- Miranda floor/bounds/terrain readiness for areas whose old primitive blockers extend beyond the current walkable floor.
- Server-authoritative multiplayer session model.
- WebGPU/OffscreenCanvas worker renderer experiments.
- Threlte integration, only when there is a real runtime/editor consumer.
- Full editor migration from the old `apps/game` reference app.
